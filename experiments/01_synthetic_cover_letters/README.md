# Experiment 1 — synthetic cover letters, controlled feature recovery

Paper: Section `sec:feature_extraction_empirical_results` (*Empirical Results on Interpretable
Feature Extraction*) and Appendix `app:experiment-details` (*Experiment Details on Interpretable
Feature Recovery*), including `app:beta-orthogonality` ("Empirical check").

A corpus of 200 cover letters is generated by templating, with 16 planted ground-truth
features ("dials": experience, education, school and employer prestige, languages, launches,
skill coverage, role skills, niche activities; prose fluency is a 17th, off-target dial). The
letters answer one job ad (`dataset/job_ad.py`: a public job posting, "Software Engineer,
Information Security Engineering"; the URL is in the module docstring). Every letter's level on
every dial is known, so feature recovery can be scored exactly.

Our method judges the letters pairwise with an LLM along a 40-regular comparison graph, groups
the judge's rationales into canonical criteria with an LLM taxonomy, and fits the gated
Bradley-Terry model, keeping the criteria that pass the κ/ρ reliability gate. It is compared
with direct LLM feature extraction (a strong model writes a rubric, a cheap model scores every
letter against it) and with two ablations that keep our criteria but replace the statistical
model with pointwise LLM scoring.

## Layout

```
config.yaml                  every setting (models, seeds, gates, κ_max = 10, ρ_min = 0.75, n*)
dataset/                     corpus generator: dials, templates, job ad, fluency degradation
prompts.py                   comparative, taxonomy, rubric-elicitation and scoring prompts
prompts_pointwise_canonical.py  the pointwise prompt of the ablation arms
scripts/NN_*.py              the pipeline, one step per file (table below)
scripts/_paths.py            puts the repo root (core) and this directory on sys.path
figures/make_*.py            the figures; they write next to themselves in figures/
results/                     every intermediate and final artifact (shipped)
reports/                     dataset verification written by step 00
raw/                         LLM response cache, Batch-API files, embedding cache (shipped)
cache, batch, .embed_cache   symlinks into raw/ under the names the scripts expect
```

All commands run from this directory. Scripts resolve paths relative to `config.yaml`; no
installation or `PYTHONPATH` is needed beyond the repository's Python environment.

## Method names

The scripts use short codes for the arms; `scripts/10_paper_tables.py` (`MAIN_ROWS`) maps them
onto the row names of `tab:main`.

| `tab:main` row | Code | What it is |
|---|---|---|
| Ours | `Ours` | pairwise judging → LLM taxonomy → gated model, κ/ρ gate |
| Direct LLM | `1a` / `M1` | rubric elicited from the **whole** corpus, each feature scored once |
| Direct LLM--Multi-score | `1b` / `M2` | same rubric, scoring repeated 20× and averaged (cost-matched to Ours) |
| Local LLMs | `2a` / `M3-taxo(1)` | rubric fused by an LLM taxonomy from E = 27 elicitations on 40-letter samples, scored once |
| Local LLMs--Multi-score | `2b` / `M3-taxo(n*)` | same fused rubric, scoring repeated n* = 6× (solved by `06d`) |
| Pairwise comparisons + LLM scoring | `PWC-32` / `PW-32 (1 rep)` | our 32 canonical criteria (33 minus the `Other` catch-all), rated 0–10 pointwise, one pass |
| …--Multi-score | `PWC-32m` / `PW-32 (n*)` | the same, averaged over n* = 14 passes |
| Reliable features + LLM scoring | `PWC-21` / `PW-21 (1 rep)` | the 21 criteria kept by the κ/ρ gate, rated pointwise, one pass |
| …--Multi-score | `PWC-21m` / `PW-21 (n*)` | the same, averaged over n* = 20 passes |

`M3a/b/c` are a clustering fusion of the same elicitations at cosine cutoffs 0.55/0.60/0.65.
They are not reported; `06d_cost_match.py` fits its $/spec model on their batch token counts,
which sets n* for 2b. The ablation arms rate our criteria, so their cost includes the
comparative pass and the taxonomy call.

## Full re-run (API)

Needs `OPENAI_API_KEY` (environment or `.env` at the repository root). The paid steps are, in
order:

```bash
python scripts/02_judge_comparative.py smoke   --config config.yaml
python scripts/02_judge_comparative.py submit  --config config.yaml
python scripts/02_judge_comparative.py collect --config config.yaml
python scripts/03_taxonomy.py --config config.yaml
python scripts/05_elicit_rubrics.py full --config config.yaml
python scripts/05_elicit_rubrics.py reps --config config.yaml --x 50
python scripts/05_elicit_rubrics.py reps --config config.yaml --collect
python scripts/06_pool_rubrics.py --config config.yaml
python scripts/06b_pool_taxonomy.py submit  --config config.yaml
python scripts/06b_pool_taxonomy.py collect --config config.yaml
python scripts/07_score_pointwise.py submit  --config config.yaml
python scripts/07_score_pointwise.py collect --config config.yaml
python scripts/07b_score_taxo_boot.py submit  --config config.yaml
python scripts/07b_score_taxo_boot.py collect --config config.yaml
python scripts/07c_taxonomy_letter_boot.py submit  --config config.yaml
python scripts/07c_taxonomy_letter_boot.py collect --config config.yaml
python scripts/07d_score_pointwise_canonical.py smoke  --config config.yaml --yes
python scripts/07d_score_pointwise_canonical.py submit --config config.yaml --yes
python scripts/07d_score_pointwise_canonical.py collect --config config.yaml
```

interleaved with the offline steps of the step table (00 → 01 → 02 → 03 → 04 → 10a → 05 → 06 →
06b → 06d → 07 → 07b → 07c → 07d, then 06e onwards as in the fast path). The whole run costs
about $12 at Batch-API prices; Batch steps take up to 24 h each. Every call is content-addressed
in `cache/responses`, so re-running a step only bills calls that are not cached. The judge,
taxonomy and rubric calls are sampled, so a fresh run reproduces the findings rather than the
exact decimals; the shipped caches in `raw/` hold the responses behind every reported number.

## Shipped inputs

The bootstrap and cost steps also read the following files, shipped in `results/`:

* `results/gated/taxo_boot_sel.json` and `results/gated/taxo_boot_groupings.json` — the matching
  resamples and the per-replicate taxonomy groupings of the Ours bootstrap (`08b`);
* `results/gated/m1_boot_resamples.json` — the 50 letter resamples shared by the letter-resampled
  bootstraps (`07c`, `08`, `08d`, `08e`, `08f`), which makes them paired;
* `results/gated/m1_boot_rubrics.json` — the per-resample Direct LLM rubrics (`08`);
* `results/rubric_stability/cost_ledger.{json,csv}` — per-call cost ledger of the rubric
  elicitations (`06d`, `08c`).
